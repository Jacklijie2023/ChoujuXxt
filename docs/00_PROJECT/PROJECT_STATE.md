## 3. RTI-001 源码审查发现：遮挡与采集策略不一致

### 已证实的源码事实

1. `ScreenCaptureManager.captureLatestBitmap(..., occludingCaptureRequired = true)` 会在遮挡必须避免的场景中选择“隐藏 Hanako 窗口 → 取隐藏后的新帧 → 恢复”路径。AppContainer 的请求兜底 OCR 明确传入 true。
2. 后台 OCR 路径使用 `captureLatestBitmap(appContext, settings.screenCaptureMethod)`，没有传入 `occludingCaptureRequired = true`，因此使用默认策略。
3. 测试中心的 `manualCaptureForTest()` 也使用默认策略。该策略可在窗口保持可见时将 Hanako 自身覆盖区域涂黑，而不是还原其背后的刷题内容；独立输入法窗口不属于 Hanako 窗口遮罩列表，因此不会因此自动消失。
4. 用户请求并不总会进入强制隐藏截图路径：`currentScreenContextForPrompt()` 先调用 `evidenceContextForPrompt()`，当已保存的题目上下文通过状态、来源和新鲜度检查时，会直接返回该上下文，不再做请求级兜底截图。
5. 因此，若当前上下文中的图像来自默认后台/测试采集，存在将被遮挡或带输入法的图像继续用于模型请求的路径可能性。代码能证明这种路径组合存在，但没有当前用户那次请求的 trace，不能把它认定为那次答题错误的唯一根因。
6. OverlayService 中实现了截图期间隐藏 Hanako 窗口、收起输入法并恢复原状态的函数；关键风险是不同调用路径是否真正使用这项事务，而不是仓库里有没有这两个函数。

### RTI-001 最小修复边界

- 对用户主动触发、并要求可用于诊断/视觉理解的受控采集，使用合适的无遮挡采集事务，明确输入法处理；若该采集必须保持窗口可见，则必须将图像标记为 MASKED/不能代表遮挡区域底层内容，并禁止将其当作完整视觉证据。
- 请求优先复用上下文前，核实当前上下文是否包含被遮挡图像或不可信视口；不能把“文本上下文新鲜”直接等同于“图像有效、无遮挡”。
- 不要简单地把所有后台探测都改为隐藏浮层，否则可能引入闪烁或干扰交互。需要区分后台低频探测、测试中心受控采集、用户请求补救采集。
- 保留现有 CaptureLifecycleLock、帧时间戳门控和 finally 等价恢复机制；禁止创建绕过 CaptureUiGate 的第二套截图实现。

### RTI-001 验收

- 测试中心产生的受控截图不再将 Hanako 浮层/输入法内容误认为题目证据；如因策略保留遮罩，界面必须明确标记该图像局限。
- 请求实际使用的图像能追溯到 evidenceId，记录采集策略、是否遮罩、输入法状态/处理结果（适用字段）。
- 成功、异常、取消、超时均恢复窗口原状态。
- 真机测试必须核对截图画面，而非只看日志中的“hidden”布尔值。

## 4. RTI-002 源码审查发现：材料可能在上下文选择阶段遗漏

### 已证实的源码事实

1. 用户提问时先尝试用当前 questionKey 从 EvidenceStore 重建上下文，再依据状态、文本非空、证据新鲜度与来源应用检查决定是否直接注入。
2. 只有 evidenceContext 被拒绝后，才进入无障碍即时读取和可能的请求级截图/OCR 兜底。
3. ChatSessionHolder 有从 ContextImageRef 加载图像 Base64、进行视觉能力门控并把已加载图像传给 streamSource 的路径；trace 记录 context version、文本指纹和实际发送图像 ID/数量。
4. EvidenceContext 组装时传入 `liveViewportCovered = true`，而本次源码审查尚未找到能证明“最新视口已被当前证据覆盖”的同一次视口校验条件。这是需进一步审计/测试的高风险点：不能仅因为 questionId 存在、证据足够新，就声称当前屏幕已被覆盖。
5. 目前没有与用户截图时间和该模型回答对应的 traceId、evidenceId、最终请求文本/图像发送状态。因此不能最终判定缺失发生于采集、过滤、组装还是模型输入阶段。

### RTI-002 最小修复边界

- 用 traceId 将屏幕采集、原始证据、分类、组装上下文、图像加载和最终模型请求串联。
- 核实 `liveViewportCovered` 的真实语义；若未验证实际当前视口覆盖，不得无条件传 true。
- 对同一题材料分散在多个视口的情况，检查排序、证据关联、分类和长度预算；关键数字不能被静默截断。
- 对图像分别记录“已保存、文件可读取、选择进入请求计划、Base64 加载成功、实际进入请求载荷”状态。
- 不硬编码这题的答案。验收以真实材料数值可追溯进入模型输入为准。

### 当前缺口（源码检查）
- 没有明确的“导出全部测试数据”或“分享为 TXT”按钮。

- 页面文本未使用 SelectionContainer 或可选取文本容器；当前实现不能确认支持聊天页面类似的长按选取体验。
- 页面存在“隐私、保留与导出”说明，但这不等于导出功能已经实现。

### 最小实现边界
- 复用项目现有 TXT 分享/文件分享和聊天文本选择实现；
- 所有导出均脱敏 API Key/令牌/密码；
- 导出包含时间、会话、证据来源/ID、原文、过滤、上下文、图像状态、trace、模型能力与错误；提供完整模块复制；
- 只读诊断界面不得因导出而触发真实模型请求或隐式截图；
- 验证长文本选择不会吞掉滚动和按钮交互。
