# ARCHITECTURE_DECISIONS — 实时互动架构决策记录

> 本文件记录有明确依据的项目级决策。状态为“冻结”的决策不能由局部施工任务自行改写；需要变更时新增决策记录，说明影响和替代方案，并取得用户批准。

## ADR-001：原始证据是唯一事实来源
- 状态：冻结
- 决策：采集结果以不可变原始证据记录保存；过滤、排序、合并和上下文拼装均为可重算派生数据。
- 原因：此前的纯文本池丢失原始图像/原始 OCR，难以回溯数据在哪一步丢失。
- 实施约束：原始 evidenceId、来源、时间、内容哈希、原始文本/节点、图像引用、错误状态应可追溯。不得用过滤后的文本覆盖原文。

## ADR-002：单一题目上下文，禁止并行真相
- 状态：冻结
- 决策：QuestionContextAssembler 的输出是实时互动唯一可注入题目上下文。迷你聊天、请求构造和测试中心都必须引用同一上下文版本与 evidenceIds。
- 原因：旧快照、文本池和发送时 OCR 并行时，可能分别代表不同屏幕或不同题目。
- 实施约束：旧上下文/文本池可以作为兼容层或诊断数据，但不能成为第二个权威上下文来源。

## ADR-003：保留现有算法零件，按证据链集成
- 状态：冻结
- 决策：优先复用 ScreenChangeDetector、ViewportMerger、PoolInjection、ScreenContentQuality、OcrTextOrganization、无障碍服务和现有 provider 适配器。
- 原因：历史审查认为问题主要在证据不可追溯、上下文不唯一、图像未接入，而不是所有算法都应重写。
- 实施约束：替换现有算法必须提供根因证据、对照测试与收益说明；禁止为了局部绕过故障新建平行管线。

## ADR-004：持续观察与发送问题分离
- 状态：冻结
- 决策：平时由实时观察链路积累证据；打开迷你对话窗口不应隐式启动重复扫描；发送时优先读取最新可证明的上下文快照。只有明确的补救策略可以触发受控新采集。
- 原因：避免发送时同步 OCR 造成卡顿、竞态、重复采集及测试难以重放。
- 验收：请求 trace 应说明上下文版本、最后采集时间、是否补采及补采原因。

## ADR-005：截图前正确处理 Hanako 覆盖层与输入法
- 状态：冻结
- 决策：需要无遮挡采集时优先真正隐藏覆盖窗口并处理输入法，采集只接受操作之后的新帧；单纯涂黑覆盖区域不能视为底层内容恢复。
- 原因：用户报告画面中悬浮球/迷你窗遮挡题目；此前日志分析也指向遮罩只涂黑 Hanako 窗口区域的风险。
- 验收：目标题目画面真实可见、旧帧被拒绝、成功与异常路径均恢复原 UI 状态。

## ADR-006：图像发送必须基于真实 payload
- 状态：冻结
- 决策：图像能力状态、文件存在、载荷包含图像、请求成功须分别记录。仅当图像实际纳入请求体时才能声明已发送。
- 原因：网络适配器支持图像不代表实时聊天路径一定传图；纯 OCR 对图表/几何/公式题有明确局限。
- 验收：用 trace 或可脱敏的 payload 摘要证明实际 image count、image/evidence IDs、provider 能力判定和发送结果。

## ADR-007：缺失/不确定信息显式呈现，禁止猜题
- 状态：冻结
- 决策：KEEP/EXCLUDE/UNCERTAIN 必须有理由与可回溯来源；跨屏是否属于同题无法确认时不得假装连续；材料缺失时列明缺失项，不能硬编码选项或依据经验补数字。
- 验收：能从上下文和 trace 找到关键数据的来源；无来源的数据不得被描述成题目原文。

## ADR-008：关闭实时互动不等于销毁历史证据
- 状态：冻结
- 决策：关闭实时模式应结束/冻结活动会话并保留已持久化证据，不得简单清空历史作为关闭逻辑。
- 原因：测试中心需要可复核数据；临时开关不应破坏诊断链。
- 未冻结事项：具体历史保留期限、容量配额、清理入口和用户同意/隐私说明，需要单独产品决策。

## ADR-009：测试中心是同源只读诊断面
- 状态：冻结
- 决策：测试中心读取 EvidenceStore、分类结果、QuestionContext 和 RequestTrace；不得另建第二套采集器/文本池。重放数据应重新过滤/组装，但默认不重新截图、不调用模型。
- 验收：界面中的数据能用相同的 evidenceId/context version/traceId 与生产请求对应；未运行、成功、失败和待真机验证清晰区分。

## ADR-010：局部问题不得自动重写主线
- 状态：冻结
- 决策：每个反馈登记为有边界的子任务，标注对应主线章节、根因证据、最小修复范围和验收项。架构变更必须提出新的 ADR 或修订提案，列明替代方案与影响，并经用户批准。
- 原因：防止因多轮局部调试而丢失此前有价值的讨论与冻结结论。

## 待决策事项（不可自行冻结）
1. 证据/图像具体保留配额、时长和自动清理策略。
2. 测试中心的完整题目正文、图片与脱敏 prompt 的可见范围、导出范围和二次确认方式。
3. 是否提供用户主动删除单题证据的能力，以及具体保护措施。
4. 若未来更改核心存储或请求架构，其迁移范围、回滚方式和额外依赖。
